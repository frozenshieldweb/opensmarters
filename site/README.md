# site/: the opensmarters landing page

One screen that says what opensmarters is, lets the visitor drive a small live replica of the
app, and offers the download (`docs/LAUNCH_PROMPT.md`, Part A). Art direction "Afterglow"
(`docs/DESIGN.md`).

Plain static files: no framework, no dependencies, no cookies, no storage, and **no
third-party requests** (every font, image and script is served from the same origin).

## Files

| File | What it is |
|---|---|
| `index.html` | **Generated** by `scripts/build.mjs`; don't edit it by hand |
| `content.js` | Every string on the page, and the product name (`PRODUCT`) in one constant |
| `release.js` | Everything version-dependent: version, files, sizes, SHA-256, signed flag, URLs, which features ship. Its `BEGIN`/`END` block is written by `scripts/update-release.ps1` |
| `page.js` | The page's markup as functions of `content.js` and `release.js` (used by the build and by the preview switch) |
| `replica.js` | The interactive replica: Live TV, Guide and Player scenes, one focus, the generated picture |
| `main.js` | Enhancements: toasts, checksums, tooltips, the ambient light, the scene tabs, the feature beats that drive the replica |
| `boot.js` | Runs before the first paint: marks that JavaScript runs and picks the download variant (Windows, phone/tablet, other) |
| `h.js`, `icons.js`, `util.js` | A tiny element tree (no `innerHTML`), Phosphor icon names, release helpers |
| `styles.css` | Tokens named after DESIGN.md, the layout, the focus treatment, the replica |
| `fonts/`, `img/`, favicons, `og-image.jpg` | Copied from the launch-asset pipeline (`assets/launch/web/`) by the build, with the licence texts next to the fonts |
| `manifest.webmanifest`, `_headers` | Generated by the build |
| `scripts/` | `build.mjs` (Node, no dependencies) and `update-release.ps1` |

Fonts: `afterglow-sans-latin.woff2` **is Source Sans 3**, subset and renamed because its licence
reserves the name "Source" for unmodified copies; `fraunces-latin.woff2` is a subset of
Fraunces. Both are SIL OFL 1.1 (texts in `fonts/`). The icons are two small subsets of the
app's Phosphor fonts (MIT, `fonts/LICENSE-Phosphor.txt`). To change any asset, change
`tools/assets/launch.toml` and rebuild with the pipeline (`tools/assets/README.md`), then run
the build here.

## Preview locally

```powershell
node site/scripts/build.mjs                      # after changing content.js, page.js or release.js
python -m http.server 8000 --directory site      # or any static server
```

Open <http://localhost:8000/>. Serve over HTTP: browsers don't run ES modules from `file://`.

- `?preview=0.2.0` (dev only, never linked) renders the page as if a 0.2.0 release with an
  installer existed, with all the 0.2.0 features. A notice says it isn't released.
- `node site/scripts/build.mjs --check` fails when `index.html` or a copied asset is out of
  date (useful in CI).

## Publish a release

**Normally automatic.** Push a `vX.Y.Z` tag that matches the workspace version in
`Cargo.toml`. `.github/workflows/release.yml` then:

1. builds the zip and the setup exe on a clean Windows runner (`tools/package.ps1`);
2. attests their build provenance;
3. publishes the GitHub Release with the notes from that version's `CHANGELOG.md` section;
4. runs `update-release.ps1` against the published files and commits `site/release.js` and
   `site/index.html` to `main`;
5. deploys the page (below).

**By hand** (a local build, or another host):

```powershell
powershell -ExecutionPolicy Bypass -File site\scripts\update-release.ps1 `
    -BaseUrl "https://github.com/frozenshieldweb/opensmarters/releases/download/v{version}"
```

It reads `dist/` (or `-Dist <folder>`): `opensmarters-<v>-windows-x64-setup.exe`,
`opensmarters-<v>-windows-x64.zip` and `SHA256SUMS.txt`. It computes every SHA-256, checks
them against `SHA256SUMS.txt` / `*.sha256` (a mismatch stops it), reads the Authenticode
status, writes `release.js` and rebuilds `index.html`. Without `-BaseUrl` the URLs stay
`TODO`. Upload the same files to where `-BaseUrl` points, and commit `site/`.

With an installer, the primary button downloads it and the zip becomes a secondary link.
Without one, the primary button downloads the zip and says so. While `signed` is false, the
page says Windows may warn about an unknown publisher.

## Deploy

The page is served by GitHub Pages from the `gh-pages` branch, at
<https://frozenshieldweb.github.io/opensmarters/>. `.github/workflows/pages.yml` copies
`site/` there (without `scripts/`, `README.md` and `package.json`) when `site/` changes on
`main`, when run by hand, and after each release. It doesn't deploy while `release.js`
lists no published files, so the "Links not set yet" state never goes public.

Pages was switched on by the first push to `gh-pages` from a maintainer's account (a push
made with the workflow's `GITHUB_TOKEN` doesn't enable it); later deploys come from the
workflow.

Any other static host works too: publish the `site/` folder as it is (Netlify / Cloudflare
Pages: publish directory `site`; `_headers` is applied).

**Security headers.** `index.html` carries the Content-Security-Policy in a `<meta>` tag.
Browsers ignore `frame-ancestors` there, so the meta has every directive except that one.
Where the host can set headers, send the full policy (it's in `_headers`, generated from
`page.js`):

```
Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; font-src 'self'; connect-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'
```

GitHub Pages can't set headers, so there the page can be framed by another site.

## Addresses

- `release.js`: `sourceUrl` is the repository; the "Licence", "Security" and "Build from
  source" links are derived from it (`/blob/main/LICENSE`, `/blob/main/docs/SECURITY.md`,
  `#build-from-source`). The download URLs are written by `update-release.ps1`.
- `content.js`: `meta.siteUrl` is the page's public address (canonical, `og:url`, absolute
  `og:image`).

## Checks used while building it (dev tooling, not needed by the page)

Lighthouse 13.5.0 and puppeteer-core 25.15.0 through `npx`/a scratch folder, with the local
Chrome. Budgets (`docs/LAUNCH_PROMPT.md` §A5): HTML + CSS + JS ≤ 120 KB gzipped, fonts ≤ 150
KB, hero ≤ 250 KB at 1920 px, CLS 0, Lighthouse ≥ 95.

Lighthouse's SEO category flags `robots.txt` as "failed to fetch": it fetches it from inside
the page, and the required `connect-src 'none'` blocks that. Real crawlers aren't affected.
